# 보안뉴스 데일리 다이제스트 작성 절차

## 왜 이런 형식인가

받는 사람은 출근길에 3분 안에 훑어보고 "오늘 신경 써야 할 게 있는지"만 파악하면 된다. 그래서 심각도 순으로 배치하고, 각 항목에 "왜 중요한지"를 붙인다. 단순 링크 목록은 다이제스트가 아니다.

## 입력 읽기

`_workspace/security-news/{YYYY-MM-DD}_collected.json`을 읽는다. 파일이 없으면 수집 단계가 실패한 것이므로, 그 사실을 짧게 알리는 안내문만 작성하고 종료한다 (빈 보고서를 지어내지 않는다).

## 카테고리 분류

각 항목을 다음 5개 카테고리 중 하나로 분류한다. 제목/스니펫만으로 애매하면 WebFetch로 원문을 확인한다 (모든 항목을 다 열람할 필요는 없다 — 판단이 필요한 항목에 한정한다).

- **보안사고** — 실제로 발생한 공격/침해/유출/장애. "~당했다", "~유출됐다", "~공격받았다" 류. KISA 공지는 보통 해당 없음(사전 예방/패치 안내이지 사고 발생 보도가 아님).
- **취약점·패치** — CVE 공개, 보안 업데이트/패치 권고. KISA 보안공지 대부분이 여기 속한다.
- **정책·규제** — 법령, 정부/규제기관 조치, 가이드라인, 제재.
- **산업동향** — 기업 소식, 통계·리포트, 제품/서비스 출시, 협력, 채용 등 즉각적인 조치가 필요 없는 뉴스.
- **기타** — 위 네 가지에 안 맞는 경우.

**보안사고로 분류한 항목은 반드시 사고유형을 함께 표시한다** (사용자가 어떤 종류의 문제였는지 바로 알 수 있어야 한다):
랜섬웨어 / 피싱·사회공학 / 데이터유출 / DDoS / 공급망공격(악성 패키지·업데이트 등) / 내부자위협 / 취약점 악용(구체적 유형 — 예: RCE, 인증우회, 경로탐색) / APT·국가배후 / 기타

취약점이 "실제로 악용되어 사고로 이어진" 경우(예: 특정 취약점을 이용한 침해가 실제 발생, CISA KEV 등재 등)는 **보안사고**로 분류하고 사고유형을 "취약점 악용(OOO)"으로 적는다. 아직 악용 사례 없이 패치만 나온 경우는 **취약점·패치**로 분류한다.

## 심각도 판단 기준

다음에 해당하면 긴급(🔴)으로 표시한다:
- 실제 악용(active exploitation) 중인 취약점
- 대규모 침해/유출 사고
- 정기 패치 주기를 벗어난 긴급 보안 업데이트 (예: "긴급", "제로데이" 표현 포함)

## 보고서 구조

이메일 발송 스크립트가 이 표를 그대로 HTML 표로 변환하므로, 표 형식(파이프 마크다운)을 반드시 정확히 지킨다 — 표가 아닌 다른 형식(불릿 등)으로 쓰면 이메일에서 표로 렌더링되지 않는다.

```markdown
# 보안 뉴스 다이제스트 — {YYYY-MM-DD}

{수집 실패한 출처가 있으면 여기 경고 문구. 없으면 이 블록 생략}
> ⚠️ KISA 보호나라 수집 실패: {에러 사유}. 이 항목은 이번 다이제스트에서 빠졌습니다.

| 카테고리 | 사고유형 | 제목 | 날짜 | 요약 | 링크 |
|---|---|---|---|---|---|
| 🔴 보안사고 | 취약점 악용(RCE) | {제목} | {날짜} | {왜 중요한지, 영향범위, 조치사항} | {링크} |
| 보안사고 | 공급망공격 | {제목} | {날짜} | {핵심 내용} | {링크} |
| 취약점·패치 | - | {제목} | {날짜} | {대상 제품/조치 요약} | {링크} |
| 정책·규제 | - | {제목} | {날짜} | {핵심 내용} | {링크} |
| 산업동향 | - | {제목} | {날짜} | {핵심 내용} | {링크} |

(보안사고가 아닌 행은 사고유형 칸에 `-`만 넣는다. 신규 항목이 아예 없으면 표 대신 "오늘은 신규 소식이 없습니다."라고만 쓴다. 행 순서는 카테고리 우선순위 — 🔴 보안사고 → 보안사고 → 취약점·패치 → 정책·규제 → 산업동향 → 기타 — 순으로 정렬하고, 같은 카테고리 안에서는 최신순으로 정렬한다.)

---
수집: 보안뉴스 {N}건, KISA 보안공지 {M}건 (신규 기준)
```

## 작성 원칙

- 링크는 반드시 collected.json에 있는 실제 URL만 사용한다. 만들어내지 않는다.
- 요약 칸은 제목을 그대로 반복하지 않는다 — 제목에 없는 정보(영향 범위, 조치 필요 여부, 왜 문제인지)를 덧붙인다.
- 과장하지 않는다. "심각한 위협"이라는 표현은 실제로 심각도 기준에 부합할 때만 쓴다.
- 톤은 간결한 보고체로 쓰되, 불필요한 수식어는 뺀다.
- 표 셀 안에 줄바꿈이나 `|` 문자를 넣지 않는다 (표가 깨진다). 요약은 한 문장으로 압축한다.
- 사고유형은 위에 정의된 어휘 중에서 고른다. 애매하면 "기타"로 두고 요약 칸에 실제로 무슨 일이었는지 풀어 쓴다 — 억지로 끼워맞추지 않는다.

## 출력

- 파일로 저장: `reports/security-digest/{YYYY-MM-DD}.md`
- 동일한 내용을 최종 응답 텍스트로도 그대로 반환한다.
